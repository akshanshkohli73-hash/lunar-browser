Review baseline: `99d2d0d` on `arena/8b00471f-lunar-browser`.

These are source-branch fixes, **not a replacement for the published v2.6.0 installer**. The application version and profile schema remain 2.6.0 / v4. ## Reproduced defects and fixes

| Area                           | Reproduction / root cause                                                                                                                                                                                                 | Focused fix                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Profile write/read consistency | A schema-valid record could be written successfully above the existing 16 MiB read ceiling, then be quarantined on restart. UTF-8 bytes and JavaScript string length differ.                                              | Validate the serialized UTF-8 size **before** touching memory, the primary file, backup or temporary files. Exactly 16 MiB remains accepted; oversized writes fail explicitly without erasing existing data.                                                                                                                                                                                                                           |
| Missing-primary recovery       | Removing a primary JSON file while leaving a valid `.bak` silently loaded defaults; the constructor returned before checking the backup.                                                                                  | Run the same schema/migration-validated recovery path for missing and corrupt primaries. Invalid orphaned backups remain untouched and produce an honest defaults warning.                                                                                                                                                                                                                                                             |
| Dashboard note drafts          | Submit a note, type more (or clear it), then deliver the save broadcast/reply: synchronization replaced the newer draft, and the UI could claim it was saved. Another note-widget save could also overwrite local typing. | Keep explicit local drafts separate from the saved snapshot. Clear only the submitted draft when unchanged; preserve later text, including an empty string. Success/unsaved/error feedback reflects the currently displayed text.                                                                                                                                                                                                      |
| Renderer snapshot ordering     | Hold bootstrap or a mutation reply, deliver a newer subscription snapshot, then resolve the old reply: settings, dashboard/wallpaper, bookmarks or Shield display rolled back.                                            | Track subscription generations independently per domain. Order successful settings/dashboard replies without allowing an older acknowledgement to replace a newer event or confirmed save. Untouched bootstrap fields, response-only saves and overlapping failures still work. Existing native-tab revision protection is retained.                                                                                                   |
| Background activity            | Deliver a blur event while the initial activity query is pending, then resolve its earlier `true` value: the background workspace became active again.                                                                    | A newer activity subscription event takes precedence over the outstanding query, preserving the inactivity policy used by wallpaper playback and rendering.                                                                                                                                                                                                                                                                            |
| Tab-session persistence        | Inject a real session-file rename failure, then queue the identical session again: the failed snapshot had already advanced the deduplication marker, so it was never retried.                                            | Extract the per-window debounce owner into `SessionSaver`; deduplicate against the validated storage cache, which only advances on successful writes and also reflects settings-originated snapshots. Keep failures eligible for the next event/close without a background retry loop. Retain the 500 ms debounce, duplicate-event suppression, opt-in/privacy clearing, latest-snapshot close flush and deterministic timer disposal. |

The persistence reproductions use actual temporary profile files and real `StorageService` restarts. The renderer reproductions use real React components/context and the validated profile service behind a controllably delayed test bridge. They are not native-Electron or GPU evidence by themselves.

## Electron runtime advisory

The full npm audit reported **GHSA-jr5w-w6x2-84p9** against the pinned Electron 44.7.2 runtime. Electron is classified as a development dependency by npm but **its binary ships in the application**, so a clean `npm audit --omit=dev` did not cover this finding.

- [Advisory](https://github.com/advisories/GHSA-jr5w-w6x2-84p9): compromised eMudhra intermediate-certificate mitigation; the affected Electron 44 range ends before **44.9.1**. No application-side TLS workaround is recommended by the advisory.
- Pin **44.11.3**, within the same Electron major, in both manifests. Only the Electron package changed in the resolved dependency graph; no dependency was added, no blanket `npm audit fix` was used, and no TLS/certificate check was disabled.
- The updated full audit reports **0 high/critical findings**, no Electron finding, and **16 remaining moderate development/build-tool findings**. Those remain visible for a separate targeted tooling review; they were not suppressed. The production-only audit reports **0** findings.
- These audit results are advisory-database checks, not a guarantee of security. The already-published v2.6.0 download retains its original runtime and does **not** gain this update. A future, separately authorized, versioned manual release is required to distribute the fixes.

## Regression coverage and scope

Added **24 tests in 3 files**:

- `tests/atomic-file.test.ts`: orphaned valid/invalid backups, oversized multibyte UTF-8 rejection with byte-for-byte preserved files/cache, a subsequent valid save, and a real fsynced **16 MiB inclusive** restart/content boundary.
- `tests/renderer-consistency.test.tsx`: notes edited/cleared during saves, pristine vs dirty subscription updates, failed-save recovery, delayed bootstrap per-domain ordering, response-only and reversed overlapping saves, overlapping failures, stale settings/dashboard acknowledgements and the background-activity race.
- `tests/session-saver.test.ts`: transient disk failure and identical-snapshot retry, no retry loop, bounded duplicate handling, latest-state debounce, return-to-saved deduplication, independently saved settings snapshots, superseded failures, opt-out clearing, final close flush and no post-disposal writes.

Tabs/navigation/view ownership, download progress/control/retention/disposal, wallpaper import quotas/protocol/media lifecycle and profile/privacy paths were also inspected and exercised by the existing suite. No speculative changes were made to the native tab manager, download manager, wallpaper store or media owner. No existing assertions, type/lint rules, optical checks, data limits or security boundaries were relaxed.
